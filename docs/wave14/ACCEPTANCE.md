## 164 Parallel Join Visualizer（状態とフィードバック）

- 表示順 A（受付）→B（会場）→C（案内）。初期の3枝はPending。Startで全枝Running。NextはB→A→Cの固定順で1枝ずつ完了させ、表示順とは別の履歴に記録する。実並行・乱数・時刻・非同期通信は使わない。
- 各枝の予定結果は Success / Failed / Cancelled から開始前に編集可。既定は B Success、A Failed、C Success。Quorumは1〜3（初期2）。初期条件は All。開始後は条件と予定結果を固定する。
- Allは全3枝のSuccessが必要、Anyは最初のSuccessで成立、Quorumは指定数のSuccess時に成立。成功数＋未完了数が必要数を下回れば成立不能。失敗・キャンセルと成立不能の理由は文字で区別する。全枝がCancelledならキャンセル扱い、成功が不可能になった時点でFailedの発生があれば失敗由来、なければ取消由来。後続記録はラッチされた成否・理由・確定順を変更しない。
- 正常対照：All・全成功→3件目Cで成立。Any・既定→初回Bで成立し、A失敗とC成功が後着しても確定保持。Quorum 2・既定→3件目Cで成立。Quorum 3・既定→2件目Aで成立不能。取消対照は全枝Cancelled。未開始でNext／不正条件／再Startを成功にしない。
- Resetで全枝Pending、既定の予定・条件へ戻し履歴と確定判定を消す。状態を文字で読む。単一経路の進行や引継ぎではなく、独立枝の合流条件と遅着結果が主題。

## 165 Variable Scope Inspector（状態とフィードバック）

- 実行手順 A1（北・収集）→A2（北・収束）→B1（南・案内）、初期 A1。共有 workflow に route=`"総合受付"`、branch A に route=`"北展示室"`、step A1 に route=`"資料棚"`。他のstep、branch Bは空。値は文字列。変数名は ASCII 英字開始、後続は英数字またはアンダースコア、長さ1〜24、値は最大80文字（空文字を区別）。
- Inspect（最寄り）では現在step→現在branch→workflowの順で名前を解決。route はA1で資料棚、A2で北展示室、B1で総合受付。明示先workflowはA1からも総合受付。明示先の見えない別branch/stepには到達せず共有値へのfallbackを禁止。「明示先に不存在」と「明示先が範囲外」を区別する。
- 任意の有効名・値を、現在位置から見える明示先にDefine/Update。現在branch/stepへの更新は他枝/stepの同名値を変更しない。赤対照は見えない先での更新と無効名（成功不可・変数集合不変）。存在しない名前のInspectは見つからない。値・名前・操作入力変更は旧Inspect結果を無効化し、同値再選択は保持。共有とローカルのラベルを文字で区別する。
- 検査、定義・更新、移動、拒否を順序付き履歴で見せる（入力を変えるだけでは操作を増やさない）。Resetで初期A1・初期変数・空履歴・未評価へ。既存の表示・保存・引継ぎではなく変数の語彙的な参照範囲が主題。
